# Sofa Engine — Phase 3: Visual drag plan-view builder (web-only)

> Phase 3 of the sofa engine roadmap (`2026-06-21-sofa-engine-roadmap.md`). The **visual drag plan-view room builder** — drag compartment modules onto a 600×480cm room, edge-snap, connected-sofa detection, arm-cap closure validation, live price. **Web-only, NO migration, NO §7 gate.** The pricing engine (P2) + the catalog data pipeline are already shipped — Phase 3 is the *thin visual client* on top.
> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use `- [ ]`. **Heavy TDD on Task 1** (the geometry must match 2990s exactly — same discipline as P2's pricing engine).
> **Grounding:** the exact 2990s geometry/UI this reproduces is in the Phase-3 ground workflow (5 readers, 2026-06-21, file:line-confirmed against `C:\Users\wenwe\Projects\2990s`). Key files: 2990s `packages/shared/src/sofa-build.ts` (pure geometry+pricing, 1667 lines) + `apps/pos/src/pages/CustomBuilder.tsx` (the drag UI, 2075 lines).

## Locked decisions (Loo, 2026-06-21)
- **Silhouettes = SVG-redraw** (NOT copy the 2990s PNGs). A `<CompartmentSilhouette>` draws body+backrest+arm rects from `{seatCount, armConfig, mechanism}` (parsed from the code) + the footprint aspect, themed with v17 tokens (flame `#C44D2B`, cool grays). 2990s's 38 SVGs are each 4-7 primitive rects → trivially derivable; auto-covers any future/renamed compartment. Photoreal PNGs remain an optional later upgrade via the existing `sofa_compartments.icon_url` (0178).
- **Builder surface = full-screen overlay** (the 2990s 3-pane shell: left module palette · center room canvas · bottom price bar). The 460px `ConfigureDrawer` is too narrow for a 600×480 canvas.
- **P3 scope = builder + live price + ADD-TO-CART.** "Add to cart" emits **ONE `DraftLine`** (client-priced, full build config in `attrs`, sku = the model's representative sofa `product_skus.sku` for mutex correctness). The server-recompute + explode-into-per-compartment-lines is **Phase 4** — P3's single line is the contract-safe interim.
- **Recliner / 电动 = still DEFERRED** (roadmap: P3 is web-only, no migration; recliner needs `product_models.recliner_upgrade_price`). The geometry `Cell` keeps the `recliners?` field for forward-compat; no seat-toggle UI + no pricing in P3 (`computeSofaPrice` already stubs `reclinerExtra=0`).

## Why P3 is safe to ship to prod (dormant gate)
The builder is enabled **only for sofa models that have offered compartments** (`model_sofa_compartments` rows, 0178). Prod currently has **0 compartments authored** → no sofa model offers any → the builder never appears → no one can build/submit a non-exploded sofa. P3 stays dormant in prod until the principal authors compartments + offered sets + sofa combos. **Deploy note:** don't author offered compartments in prod until Phase 4 (explode) ships, so the interim single-line path is never exercised by a real order. (The builder is fully testable in dev with seeded data.)
