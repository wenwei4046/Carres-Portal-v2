- `hr-rpc-null-role-gate-shape` — HR-O1 (2026-07-26, noticed while verifying 0265): every `hr_*` DEFINER function opens with `if (select public.app_role()) not in ('hr','principal') then raise exception 'forbidden'`. When `app_role()` returns **NULL** — an authenticated Supabase user with no `app_users` row, e.g. an orphan left behind if `auth.admin.createUser` succeeded but the `app_users` insert then failed — `NULL not in (...)` evaluates to NULL, the `if` is NOT taken, and the function proceeds. The gate is open-on-unknown where it should be closed. Not known to be exploitable today (accounts are minted through routes that roll back on failure, and every caller also passes Hono's `requireHr`), which is why this is MEDIUM rather than HIGH — but it is the wrong default for a permission check and it is copy-pasted across 0244/0245/0250/0252/0254/0259/0260/0265. Firm fix: one sweep replacing the predicate with `coalesce((select public.app_role())::text,'') not in ('hr','principal')`, applied to every `hr_*` / `org_*` DEFINER function in one migration, plus a test that a role-less JWT gets 403. Do it as its own pass — it touches too many functions to ride along with a feature.
